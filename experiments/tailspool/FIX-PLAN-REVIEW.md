## 实施与验收

### #9 在建立折叠器时验证实际策略

在 OTTL 条件解析或函数绑定阶段记录真实的时间函数调用；建立 fold plan 时检查 span、span event 及复合策略的子 evaluator。扩展返回已知 OTTL 类型也走同一检查，错误包含策略名和有问题的条件。内存模式继续按决策时刻求值。

复测发现不含 Now 的 `Year(Time("01-10", "%m-%d", "UTC")) == 2026` 也跨时刻改变决定。验收增加缺年份反例及完整日期对照。

验收覆盖 `Now()`、`Now ()`、嵌套调用、字符串常量包含相同文本、外部扩展返回内置及未知 evaluator。依赖当前时间的用例在 spool 启动阶段返回错误，普通条件能启动并与内存路径逐 span 对账。

### #3 只落实 checkpoint 文件同步

按原设计在完整快照和最后一批 tail 已 Flush 后，对临时文件执行 Sync，再 rename。覆盖 Open 的初始 checkpoint 和运行时后台 checkpoint。仅在锁外同步静态快照会漏掉之后追加的 tail。对最终同步需记录持锁时间，核对是否抵消此前将大快照移出锁的优化。

验收以系统调用顺序和故障现场为准。注入文件 Sync 失败，Open 返回错误；运行时按 WAL 计划持锁非零退出，旧日志仍可回放。测试机复测 checkpoint 期间的 ACK p99、最大值和吞吐，并对照现有 SIGKILL 恢复。交付承诺仍限于同机进程退出后的可回放范围。

### #1 确认永久拒绝的交付策略后实施

若要求保留已 ACK 的 keep 数据，优先评估将被明确永久拒绝的 record 持久隔离，释放交付 worker，并定义容量、告警、重启和人工重放。若业务接受下游永久拒绝为终局丢弃，可采用已试验的轻量方案：仅识别显式 permanent 错误，单计拒绝记录与 span，Flush C 成功后释放，写 C 失败沿用 WAL 致命路径。探针中该方案三轮均为 16 条拒绝、1 条健康交付、重开后 0 条 live；这证明能解除阻塞，不能替代丢弃授权。两种策略均应保留暂时错误重试，并核对实际 exporter 的发送队列决定哪些错误会同步返回。

### 条件性工作及启用标准

- **#2（已通过）** 用真实 OTLP 客户端从独立请求字节重发，分别强制队满超时和磁盘阈值拒绝。核对失败尝试没有 T、成功重发产生一次登记、sink 端身份、字段与重数完整。只有受支持路径也失败，才进入正确性修复；若主动增加同对象重试兼容性，则另作 API 扩展评估。临时回滚移动操作的方案已通过 32 span、133,240 字节逐字节对照，不能据此把额外开销加给所有正常请求。
- **#5** 若要支持可解码但与 WAL 不一致的损坏段，先检测并报告缺失关联及 seq、段号，再确定保留现场或逐关联处置。部分匹配时直接对整条写 C 会连带放弃健康数据。验收需同时包含正常上游改写、全部失配和部分失配。
- **#7** 若部署要求可控停机，给恢复退避增加关闭信号；中断时保留尚未完成的记录供下次恢复。分别验证正常运行仍遵循 read_retries、关闭不会把取消记作读失败耗尽、重启能继续处理原记录。
- **#8** 在将 spool 发布到无 flock 的目标平台前，选择原生互斥或明确拒绝启用。以目标平台两个真实进程争用同目录、首进程退出后再次成功打开为验收。Linux 继续运行现有锁回归。

## 本次实施与验收

- **#9** 启动时由 Fold 检查已经绑定的 OTTL 函数。span、span event、嵌套子策略及扩展返回的内置 evaluator 走同一路径。拒绝 `Now`、生成随机值的 `UUID`、依赖时间与随机数的 `UUIDv7`，以及可能推断年份的 `Time`。日期字面量按实际格式、时区与语言解析，完整非零年份可折叠。`Time` 的输入若来自运行时字段，当前采用保守拒绝；显式四位年份也可能传入 `0000`，触发解析器的补年逻辑。内存路径仍接受这些条件。
- **#3** Open 和后台 checkpoint 在安装同一个临时文件前执行文件 Sync。后台在持锁补完 tail 后同步，随后才 rename。Sync 失败时，Open 返回错误；运行中在锁内致命退出，旧 WAL 可重新打开并回放。继续沿用同目录 rename 边界。
- **测试机** `10.98.1.5`，本次正式版本证据目录为 `/mnt/otelbench/tailspool-reviewfix-oLHxeJ/out/`。三轮定点回归见 `target.log`，模块完整 race 见 `final-race.log`，时间解析和 OTTL 函数包回归见 `timeutils.log`、`timefunc.log`。扩展拒绝与确定性日期实际导出对照见 `extension.log`、`date.log`。真实 OTLP 重发三轮见 `transport.log`。
- **系统调用** 在初始、后台及重开检查点的并发 tail 用例中跟踪到 30 次临时文件 fsync、30 次 rename；逐个安装比对见 `checkpoint.strace`。启动 Sync 故障恢复旧记录，运行时 Sync 故障子进程退出码 1，旧日志 inode 得以保留。
- **真实 Collector 对账** 每组 6,000 个请求、768,000 个 span 身份槽位，内存基线保留 94,171 个 span。正常 spool 和三次 SIGKILL 重启后的 spool 逐身份对照均为缺失 0、额外 0、重复 0。故障组客户端有 32 个请求重试。见 `spool-200.report.txt`、`kill-200.report.txt`、`e2e.log`。
- **checkpoint 开销** 在同一 ext4 测试卷交替运行原 Flush 和正式 Sync 版本，各三轮，每轮 4 个客户端、4,000 个 OTLP RPC、16 次主动 checkpoint。末次快照约 1.9 MB，每次均带非空 tail。各轮安装阶段持锁中位数由 0.298–0.340 ms 升至 3.196–3.430 ms，客户端 ACK p99 由 1.075–1.478 ms 升至 3.412–3.775 ms；最大 ACK 由 4.709–16.002 ms 升至 6.996–36.468 ms。吞吐分别为 14,055–18,656 和 10,727–13,822 RPC/s。保留文件 Sync，以上数值用于高频 checkpoint 压测对照。见 `flush-pilot.log`、`fixed-pilot.log`。
